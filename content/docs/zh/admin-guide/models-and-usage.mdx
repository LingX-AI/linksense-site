先配置可用模型，再设置额度标准，最后用实际统计和账单核对使用情况。

## 模型与生成能力设置 [#model-settings]

<Callout type="info" title="管理员操作">

进入“设置 → 模型设置”。修改只影响后续新轮次或新文档处理，不改写正在运行和历史记录。

</Callout>

### 模型渠道 [#model-settings-模型渠道]

添加渠道时，先选择服务商，再填写名称、Base URL 和 API Key。选择服务商会填入该服务推荐的连接地址与协议；没有预设地址时，需要填写你已开通的兼容服务地址。推荐值只是配置起点，仍应核对账号、区域和服务实际支持的能力。协议模式直接显示在“高级设置”中，可以按需调整。

通过“当前渠道”切换查看模型列表，在渠道的三点菜单中选择“编辑渠道”，打开居中弹窗。打开已有渠道不会重置其连接地址或协议。API Key 保存后不回显；服务商、连接地址、项目和区域均未改变时，编辑留空可保留已有密钥。更换这些连接信息后，必须输入新连接的密钥才能保存或测试。

添加渠道时只需配置连接信息并保存，再通过“添加模型”单独配置模型。尚未添加模型的渠道不会出现在输入框的模型选项中。列表只显示模型名称、类型、价格和对话可选状态，点击编辑按钮打开模型设置弹窗。保存只提交当前弹窗的修改，取消时可以放弃未保存内容。

### 获取模型与测试连接 [#model-settings-获取模型与测试连接]

保存渠道后，选择“添加模型”，点击模型选择框右侧的“获取可用模型”，按模型名称或 ID 搜索并选择。获取列表前，模型选择框不可用。若服务不提供模型列表、列表为空或找不到目标模型，选择“手动输入模型”，填写服务商提供的模型 ID。

系统仅填入服务实际返回的模型名称、上下文长度和图片输入信息；未提供的能力会提示需要确认。模型价格需要按服务商实际收费人工核实，默认零价仅用于本地用量估算。价格、推理强度、上下文长度和图片能力直接显示在模型的“高级设置”中，无需展开。

“获取可用模型”和“测试模型连接”是独立操作：获取列表成功不代表模型调用成功。渠道编辑时可以填写用于测试的模型 ID；添加或编辑对话模型时可以直接测试当前模型。测试会发送一条简短消息，收到模型正常的非空文本回复就表示连接成功，无需模型调用工具。测试可能产生少量费用，但不会保存设置。成功结果只适用于当时的连接和模型，修改后应重新测试；它不能替代实际任务、图片理解或知识检索的功能验证。Embedding 与 Ranker 模型暂不支持这里的连接测试，按下文的知识库检索设置验证。

首次配置时，保存第一个对话模型并保持“对话可选”开启，系统会将它设为对话默认模型和任务自动命名模型。完成后返回“新任务”，检查模型与推理强度，再提交一条简单请求验证使用效果。

### 协议模式 [#model-settings-协议模式]

协议模式包括：

- 原生 Responses：上游完整支持所需 Responses 与工具类型。
- Responses 工具兼容：上游只接受标准 function 工具。
- Chat Completions 转换：上游只提供兼容的 `/chat/completions`。

兼容层只转换协议形状，不代执行工具或重放整个轮次。

### 模型 [#model-settings-模型]

模型 ID 在全部渠道中唯一。配置显示名称、类型、服务商、图片输入能力、支持推理强度和价格：

- 对话模型：输入、缓存输入和输出单价。
- Embedding 与 Ranker：输入单价。

价格单位为美元/百万 Token。保存时的价格会固化到后续用量事实；调价不重算历史费用。

“模型上下文长度”填写大于 0 的 Token 数；留空时由系统自动探测。该值用于任务中的背景信息窗口用量展示，并让运行环境在接近模型上限前自动压缩上下文。应按服务商和模型真实能力填写，不能把更大的数字当作扩容方式。

只有对话模型显示“对话可选”开关，Embedding 与 Ranker 模型不显示。“对话可选”只控制对话输入框的模型列表，不影响任务自动命名、知识检索、结果重排或图片理解。已配置对话模型时，必须至少保留一个“对话可选”的对话模型；取消默认模型的“对话可选”状态或删除默认模型时，会选择其他“对话可选”模型。

对话模型的“支持的推理强度”可以多选，候选档位为轻量、中、高、超高、最高和极致，并且至少保留一项。“默认推理强度”只能从已勾选档位中选择；取消当前默认档位时，系统自动改为剩余第一项。

### 模型排序 [#model-settings-模型排序]

拖动模型左侧的排序手柄，或在行末操作菜单中选择“上移”“下移”，调整当前渠道内的模型顺序。排序手柄也支持键盘：空格选中，上下方向键移动，空格确认，Esc 取消。

通过“渠道操作”菜单中的“上移渠道”“下移渠道”调整渠道顺序。排序调整后自动保存，失败时保留原顺序并显示提示。对话输入框按渠道顺序、渠道内模型顺序展示已开启“对话可选”的对话模型，排序不会改变用户当前选择的模型。

### 对话与任务自动命名模型 [#model-settings-对话与任务自动命名模型]

模型渠道列表末尾可以分别选择对话默认模型和任务自动命名模型。对话默认模型只允许选择“对话可选”的对话模型；任务自动命名模型可以选择任意已配置的对话模型，不读取部署环境中的内置命名模型。自动命名产生的输入、缓存输入和输出 Token 会单独计入“任务自动命名”用量；供应商未返回用量时显示为估算。

### 记忆提取模型 [#model-settings-记忆提取模型]

在模型选择区域，从已配置的对话模型中选择“记忆提取模型”。系统直接使用该模型已有的渠道、凭据和价格，无需重复填写连接信息；“对话可选”开关不影响它用于记忆提取。被引用的模型或渠道需要先解除记忆提取选择，才能删除。

选择“使用当前任务模型”时，每个任务使用自身的模型提取记忆。无论是否选择专用模型，提取均采用该模型已配置的最低受支持推理强度，不改变任务本身的推理强度。此设置只影响提取，整合仍使用当前任务模型。

只有用户主动开启记忆后才会生成记忆。配置更新用于后续启动的任务运行环境，已有记忆不会被清空。记忆状态由用户内的多个任务共享，并由原生引擎根据处理进度、作业锁和输入变化防止重复处理；切换模型或重启不会重置这些状态。失败恢复或历史更新仍可能产生新的模型调用，防重并不等于零重试或费用上限。

### 用户额度 [#model-settings-用户额度]

用户额度在独立的[额度管理](#quota-settings)页面配置，单位为 credits。

### 知识库检索模型 [#model-settings-知识库检索模型]

选择一个已配置的 Embedding 模型，并可选 Ranker 模型。“对话可选”状态不会影响这些系统模型。保存会真实调用服务，验证连接和向量维度。

<Callout type="warn" title="切换 Embedding 模型">

切换会立即使全部现有知识库索引失效，检索不可用，直到在“系统健康”完成全量索引重建。先评估维护窗口，再确认切换。

</Callout>

Ranker 未配置或调用失败时，系统使用等权 RRF 结果，不会阻断基础混合检索。

### 文档图片理解 [#model-settings-文档图片理解]

可选择已配置且标记为“支持图片理解”的对话模型；“对话可选”状态不会影响图片理解。保存时会真实探测图片输入、结构化输出和关闭思考能力。配置只影响后续新处理或重建的文档，不改写既有解析内容。

### 语音转文字模型 [#model-settings-语音转文字模型]

启用后，普通任务和嵌入应用的麦克风输入会使用这里的服务。选择已开通的服务商，确认 Base URL，填写 API Key 和模型或部署名称；Azure OpenAI 还需要 API 版本。已保存的 API Key 不会回显，编辑时留空会保留原密钥。

可选服务商包括阿里云百炼、OpenAI、OpenAI 兼容服务、Azure OpenAI、Groq、Deepgram、AssemblyAI、ElevenLabs、Rev.ai、Gladia 和 fal.ai。服务商预填值只是连接起点，实际模型、区域、权限和计费以你的服务商账号为准。

保存后使用[语音输入](../user-guide/tasks/index.mdx#voice-input)验证一段不含敏感信息的短录音。关闭该设置后，新的语音转文字请求不可用，但普通文字任务不受影响。

### 图片生成模型 [#model-settings-图片生成模型]

启用后，用户可以在任务中调用内置图片生成能力。选择服务商、填写模型和 API Key，并配置单张图片价格；该价格按实际生成张数记录到用量与 credits。选择服务商会填入默认 Base URL，所有服务商都可以改为自己使用的服务地址。

支持阿里云百炼、OpenAI、OpenAI 兼容服务、Google Gemini、Stability AI、fal.ai、Replicate 和 Together AI。OpenAI 兼容服务使用图片生成接口，请填写服务提供的 Base URL、API Key 和模型名称。阿里云百炼还需要 Workspace ID 与区域。各服务商和模型允许的最大生成张数不同，单次请求最多 10 张；运行时会按当前模型上限截取。

透明背景可以由模型原生生成，或在适合清晰边缘的场景下自动处理。复杂的头发、毛发、玻璃、烟雾、发光和半透明边缘应选择原生支持透明输出的模型。

图片编辑沿用此处配置的服务与模型，无需重新保存已有配置。可使用 OpenAI GPT Image、Gemini 图片模型、百炼 Qwen Image 2.x 及更新版本或 Qwen Image Edit，以及 fal.ai 的 FLUX.2 Edit / Kontext、Replicate 的 FLUX Kontext、Together AI 的 FLUX.2 / Kontext。OpenAI 兼容服务必须实现 `/images/edits` 文件上传接口；仅支持 `/images/generations` 的服务无法用于编辑。当前 Stability 适配器只提供文生图。具体参考图数量及蒙版支持受模型限制，无法支持的要求会在调用前被拒绝。

API Key 保存后不会回显，编辑时留空会保留原密钥。切换服务商时应填写该服务商的新密钥并核对价格。配置后可按[生成图片](../user-guide/tasks/index.mdx#generate-images)进行一次单图验证。

## 额度管理 [#quota-settings]

管理员进入“设置 → 额度管理”，设置 credits 换算价格和全体成员统一使用的周额度标准。

### Credits 换算 [#quota-settings-credits-换算]

设置 1 credit 对应的美元金额，默认是 0.01 美元。例如，一次调用费用为 0.25 美元时，将消耗 25 credits。金额必须大于 0，最多支持 6 位小数。

模型单价仍在模型设置中配置，单位为美元/百万 Token。费用根据调用量及当时的模型价格计算，credits 按记账时的换算价格记录。修改换算价格只影响之后记录的消费，不重新计算已经记录的 credits。消耗保留 6 位小数，不足精度的部分向上取整。前端展示剩余 credits 时截去小数位，实际余额和使用判断仍保留小数精度。

### 成员周额度 [#quota-settings-成员周额度]

成员周额度是之后由管理员创建、Excel 导入或自主注册成员的统一默认值。输入正数，最多支持 6 位小数；留空表示不限额。周额度按系统时区在每周一零点自动重置。

直接保存只更新默认值，不覆盖已有成员的个人周额度。已有成员仍可在“用户与用户组 → 用户”中单独或批量调整。开放注册开关位于“系统设置 → 开放注册”，但自主注册用户不再使用另一套额度标准。

### 一键重置与应用到全员 [#quota-settings-一键重置与应用到全员]

额度管理提供两个即时批量操作。点击按钮后先弹窗确认；取消弹窗不会修改额度。

- **重置全员额度**：把所有已有成员的周额度恢复到各自现有限额的 100%。该操作不改变成员的限额；不限额成员仍保持不限额。
- **应用限额到全员**：保存表单中的成员周额度，并立即覆盖所有已有成员的个人周额度，包括曾单独调整过的值。留空会将所有成员设为不限额。该操作不清零已经使用的额度，也不保存换算价格表单中的其他未提交修改。

两个操作都包含正常和已禁用成员，且不会改变账号状态。历史消费记录会保留。重置后发生的消费继续扣减，日历周重置规则也保持不变。

如果要让全部成员使用新限额并恢复到 100%，请先“应用限额到全员”，再“重置全员额度”。

周额度耗尽后，用户不能发起新任务或后续请求。已经运行的任务会继续完成，最终消耗可能超过上限。调整周额度不会删除或重新计算已经记录的 credits。

Token 和美元费用统计继续保留，额度管理不提供充值或支付功能。

## 用量、费用与账单 [#usage]

<Callout type="info" title="管理员操作">

进入“设置 → 用量统计”。“用量统计”标签页用于观察资源事实，“账单”标签页用于查看已结算的自然月模型账单；额度仍在“额度管理”中设置。

</Callout>

用户 credits 额度在[额度管理](#quota-settings)中配置，已有用户额度在“用户与用户组 → 用户”中调整。

### 时间范围 [#usage-时间范围]

选择全部时间、最近 7 天、最近 30 天，或自定义开始和结束日期。趋势会根据范围自动按日、月或年汇总。

### 统计视图 [#usage-统计视图]

- 全局：任务、实际轮次、模型调用、总 Token 和总费用。
- 工作负载：AI 回答、任务自动命名、记忆生成、文档向量化、检索查询向量化、结果重排和图片生成。
- 模型：生成、嵌入、重排和图片模型的采集方式、调用、轮次、Token 分项和费用。
- 应用：按任务创建时关联的应用汇总任务、轮次、模型调用、Token、费用及逐模型明细；未通过应用创建的用量进入“未关联应用”。
- 用户组：按查询时有效成员关系覆盖成员数据。
- 用户：启用或停用用户的用量、当前组和逐模型明细。

Token 使用 K、M、B 缩写，任务、轮次、调用和成员数显示完整整数。

### 计数口径 [#usage-计数口径]

- 任务在创建时记录一次不可变活动事实。
- 轮次只统计真实创建的执行轮次；草稿、排队、重连和重复事件不重复计数。
- 原生累计 Token 快照按增量去重。
- 外部嵌入和重排优先使用可信 usage；没有时只对实际输入估算并标记。

### 费用 [#usage-费用]

费用使用调用发生时的模型单价快照计算，币种为美元。缓存输入是输入子集，推理输出是输出子集，不重复计费。

- 后续调价不重算历史。
- 0 美元是有效价格。
- 无可靠历史价格的 Token 计入“未定价 Token”，不会用当前价格补算。

### 用户组注意事项 [#usage-用户组注意事项]

一个用户属于多个组时会计入每个组，因此组行不能相加推导全局总量。没有有效组关系的用户进入“未分组用户”。

### 排序与导出 [#usage-排序与导出]

明细表可以按页面提供的列排序。“导出 Excel”会使用当前时间范围和筛选口径生成多工作表文件，包含摘要、趋势，以及模型、用途、应用、用户组和用户等当前报表维度及其明细。导出前再次确认范围，并按组织政策保存和传递文件。导出不会包含提示词、回复正文、文件内容或凭据。

### 月度账单 [#usage-月度账单]

切换到“账单”标签页，可以查看本月账期和已经生成的月度账单。账单按系统时区的自然月结算，在月份结束后自动生成；本月卡片会显示预计生成时间。服务恢复或升级后也会补齐缺失的已结束月份。

月度账单是按模型汇总的不可变费用快照，包含输入、缓存输入、输出、总 Token、计价方式和金额：

- 同一模型整月使用一种价格时显示对应的每百万 Token 单价；月内发生调价时标记为“月内多种单价”。
- 没有可靠价格快照的 Token 显示为未计价，不会补用当前价格。
- 账单只按模型汇总，不包含提示词、回复、文件内容、用户明细或额度设置。
- 已生成账单不会因后续调价、任务删除或成员关系变化而重算。

选择一份账单可以在线查看模型明细，或按当前界面语言导出 PDF。导出操作会写入审计日志；下载后应按组织的账单和财务资料保留规则保存。

### 数据保留 [#usage-数据保留]

任务硬删除后，任务、轮次、模型调用、Token、费用、应用归属事实和已经生成的月度账单仍保留。记录不包含提示词、回复正文、文件内容、凭据、Base URL 或 API Key。
