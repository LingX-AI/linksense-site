统一审核共享能力、治理知识库状态和维护数据源连接。治理权限不会自动授予用户内容的读取权限。

## 插件中心与应用中心审核 [#plugin-governance]

<Callout type="info" title="管理员操作">

进入“设置 → 插件中心”。管理员审核的是用户提交的发布快照，不是用户可随时变化的个人目录。

</Callout>

### 审核发布 [#plugin-governance-审核发布]

在“上架审核”中打开待审发布，核对：

- 发布者、能力类型、发布序号和发布说明。
- 包内文件列表、可执行位和内容 SHA-256。
- Manifest、Skill 正文和 Logo。
- MCP server、脚本、外部连接、环境变量、凭据与依赖下载等风险声明。

每个新发布都必须单独审核。通过前系统再次校验快照完整性。

### 审核应用中心版本 [#plugin-governance-审核应用中心版本]

应用中心的待审版本会同时显示应用创建者、普通或交互式类型、版本号、版本说明和使用方式。打开审核详情后检查应用指令、插件与 Skill 名称、知识库和 MCP 数量；交互式应用还会显示包内文件路径。

“应用安装包”会复制为使用者独立维护的应用，使用者能够查看应用源码并自行配置可能需要的凭据；“在线应用服务”无需安装为使用者自己的本地应用，使用创建者维护的资源和已配置凭据在线运行。交互式应用不能以上传安装包的方式分发，只能作为在线应用服务。确认发布说明与实际能力相符，并评估指令、外部连接、数据范围和所选使用方式后再通过；拒绝时必须填写原因。

### 通过或拒绝 [#plugin-governance-通过或拒绝]

- 通过：该不可变发布成为当前版本；首次通过使条目公开上架。
- 拒绝：必须填写明确原因，不影响之前已通过版本和已有安装。

管理员发布者可以审核自己的发布，但仍应遵循组织的双人复核政策（如有）。

### 停用与恢复 [#plugin-governance-停用与恢复]

发现风险时可以在“全部上架项”中停用条目并填写原因。停用后：

- 插件中心隐藏条目。
- 阻止新安装和更新。
- 所有已安装副本不能开始新的任务。
- 已经运行的轮次继续使用启动时快照，不被强行改写终态。

恢复后条目重新公开，已有安装可用于后续新任务。

应用中心使用独立的上架状态。管理员下架应用时必须填写原因；新的安装和服务启动会被阻止，既有任务历史保留。已经独立安装的应用包不会被远程删除，仍按其个人资源状态和平台能力治理规则运行。恢复上架后，符合授权条件的用户可以重新安装或使用服务。

### 下架与停用的区别 [#plugin-governance-下架与停用的区别]

- 发布者下架：不再接受新安装，但已有安装可以继续运行和显式更新。
- 管理员停用：风险治理状态，已有安装的新任务也被阻止。

### 审计与隐私 [#plugin-governance-审计与隐私]

审核、拒绝、撤回、上下架、停用和恢复都会写入脱敏审计。应用审核只展示提交版本所需的指令和资源摘要；治理权限不授予管理员读取或修改用户未提交的个人插件、Skill 或应用草稿。

## 知识库治理 [#knowledge-governance]

<Callout type="info" title="管理员操作">

进入“设置 → 知识库”。页面提供跨用户治理元数据，不自动授予文档正文、预览或下载权限。

</Callout>

### 查找知识库 [#knowledge-governance-查找知识库]

按名称或所有者搜索，并按生命周期、可用状态和来源查看。列表展示安全元数据、文档与容量汇总，不返回文档内容。

### 可用治理操作 [#knowledge-governance-可用治理操作]

- 停用或启用：控制所有用户后续新任务是否可以使用。
- 归档：把知识库变为只读。
- 永久删除：只允许删除已归档知识库，操作不可撤销。
- 重试失败清理：重新处理资源清理任务。
- 撤销访问：移除指定授权来源。
- 转移所有者：选择其他启用用户。

需要填写原因的操作会把原因写入脱敏审计。删除仍需在归档后单独确认。

### 所有者被停用 [#knowledge-governance-所有者被停用]

知识库继续保留，既有接收方仍按权限使用。被停用所有者不能维护；管理员可停用知识库或把所有权转移给有效用户。

### 检索与索引异常 [#knowledge-governance-检索与索引异常]

单个文档失败由所有者在知识库中重试。部署范围的嵌入维度变化或索引失效应在“系统健康”执行全量重建，而不是逐个修改用户知识库。

### 权限边界 [#knowledge-governance-权限边界]

治理动作必须与内容访问分开。若管理员需要查看文档，应由所有者按正常分享流程授予访问；不要使用治理接口绕过。

## 知识库数据源 [#knowledge-sources]

<Callout type="info" title="管理员操作">

进入“设置 → 知识库 → 知识库数据源”。当前界面集中管理 SharePoint 等外部数据源连接。

</Callout>

### 配置 SharePoint [#knowledge-sources-配置-sharepoint]

填写页面要求的 Microsoft Entra 应用与租户信息，保存时 LinkSense 会验证应用身份。密钥只在提交时接收，保存后不回显。

建议使用 `Sites.Selected` 并由 Microsoft 365 管理员只为允许同步的 Site 分配读取权限，避免租户范围过大。

### 创建外部知识库 [#knowledge-sources-创建外部知识库]

数据源启用后，管理员可以在创建知识库时粘贴 SharePoint 目录 URL。LinkSense 会再次验证该具体目录的访问权限，然后建立同步。

### 同步行为 [#knowledge-sources-同步行为]

- 新文件进入与本地上传相同的校验、解析、切片、向量化和索引流程。
- 内容变化会创建替换版本。
- 仅名称变化会重命名。
- 远端删除进入受控引用、索引、对象和配额清理。
- 不支持格式会记录为跳过，不会持续重试并阻塞其他文件。

### 故障处理 [#knowledge-sources-故障处理]

身份验证失败时检查租户、应用 ID、秘密是否有效，以及 Microsoft 365 侧是否已经授予目标 Site 权限。不要在审计、工单或聊天中粘贴 client secret。

配置合法但外部服务暂不可达时，LinkSense 不会自行修改或重建外部服务。恢复连接后按页面状态重试同步。
