从发现和安装能力开始，再按需要创建、管理和共享自己的技能与应用。

## 发现、安装与更新能力 [#discover-and-install]

插件中心把公开发布的插件、Skill、MCP 扩展和应用集中在一个入口中。

“ClawHub 技能仓库”是独立的外部 Skill 来源。其安装前检查和信任边界见[从 ClawHub 安装 Skill](#clawhub)。

### 浏览与搜索 [#discover-and-install-浏览与搜索]

1. 从侧边栏进入“插件中心”。
2. 在“插件中心”标签中选择插件、技能、MCP 或应用。
3. 使用搜索框按名称、说明或发布者筛选。
4. 打开详情，检查发布者、发布说明、风险摘要、Manifest 和内容哈希。

### 安装 [#discover-and-install-安装]

选择“安装”后，LinkSense 会把当前获批发布安装到你的个人范围。安装前重点检查：

- 是否包含可执行脚本或 MCP server。
- 是否会访问外部服务。
- 是否需要环境变量或个人凭据。
- 发布者是否可信，发布说明是否与预期一致。

安装完成后，可在“已安装”或“我的能力”中启用、停用和管理。

应用使用单独的分发流程。被共享的应用会出现在“应用 → 共享给我的”，公开上架的应用位于“应用中心”；根据创建者提供的使用方式，你需要安装为自己的独立应用，或安装在线应用服务后再使用。具体区别见[使用组织应用](#organization-apps)。创建者可以[创建和管理应用](#create-applications)。

### 更新 [#discover-and-install-更新]

出现“有更新”时，可以打开详情比较发布说明并更新。更新只在你明确确认后发生；插件中心的新发布不会自动替换已有安装。

### 卸载 [#discover-and-install-卸载]

卸载会删除你的安装副本和相关个人配置，不影响插件中心中的发布。已经完成的任务和历史使用记录不会因此消失。

<Callout type="warn" title="停用与风险">

管理员可以因风险停用某个上架项。停用后条目会从插件中心隐藏，已安装副本也不能用于新的任务，直到管理员恢复。

</Callout>

## 从 ClawHub 安装 Skill [#clawhub]

ClawHub 是外部 Skill 来源。LinkSense 展示同步到本地的元数据，但不代表 ClawHub 对内容进行审核，也不为第三方 Skill 背书。

### 查找和核对 [#clawhub-查找和核对]

进入“插件中心 → ClawHub 技能仓库”，按名称搜索，并可按下载次数或收藏数排序。打开详情后核对作者、版本、更新时间、主题、平台要求、更新说明和 ClawHub 原始页面。

下载量和收藏量只能帮助了解使用情况，不能替代安全检查。

### 安装或更新 [#clawhub-安装或更新]

1. 选择要安装的版本。
2. 等待 LinkSense 获取并校验技能包。
3. 阅读来源、完整性和风险提示。
4. 确认后安装到个人 Skill。

已有同来源 Skill 时，页面会提供更新；同一版本不会重复安装。安装完成后仍可在“我的能力”中查看和管理。

### 安全与可用性 [#clawhub-安全与可用性]

被标记风险、缺少可安装版本、平台要求不满足或完整性校验失败的 Skill 可能被阻止安装。不要绕过提示，也不要把未知 Skill 所需的凭据当作普通配置随意填写。

仓库暂时不可用或尚未同步到数据时，稍后刷新。卸载只删除你的个人副本和相关配置，不影响仓库中的元数据，也不删除已经完成的任务历史。

## 管理个人插件与 Skill [#personal-content]

“我的能力”用于管理只属于你的插件和 Skill。个人内容不会自动对其他用户可见。

### 导入 ZIP 能力包 [#personal-content-导入-zip-能力包]

1. 进入“插件中心 → 我的能力”。
2. 选择添加能力和“本地压缩包”。
3. 上传符合插件或 Skill 结构约定的 ZIP 文件。
4. 等待 LinkSense 解析来源、Manifest、文件和风险声明。
5. 核对预览，勾选风险确认后安装。

预览有有效期；过期后需要重新检查。不要安装来源不明或风险声明与预期不符的包。

### 手动创建 Skill [#personal-content-手动创建-skill]

选择“手动创建 Skill”，填写完整 `SKILL.md` 内容。安装前页面会显示正文预览和检测到的能力声明。

先填写技能标识，再填写可选的展示名称。展示名称会根据标识自动生成，例如 `meeting-notes` 显示为“Meeting Notes”；你可以改成“会议纪要助手”等包含中文和空格的名称，也可以清空。修改或清空后，再调整标识不会覆盖你的选择。展示名称最多 64 个字符，不影响技能的调用标识。

导入的技能如果自带展示名称，LinkSense 会保留它；没有展示名称时，会根据技能标识显示易读标题。已有技能无需重新导入。

任务中生成的 Skill 也必须先形成可下载的完整 ZIP 包，再由你确认是否安装；生成文件本身不等于已经安装。

### 在对话中查看和卸载 Skill [#personal-content-在对话中查看和卸载-skill]

你可以对助手说“列出我所有已启用的技能”。列表包含可用的内置 Skill，以及你创建、导入或从插件中心、ClawHub 安装的个人 Skill，不受当前任务是否选中这些技能的限制。停用或失败的技能、完整插件包及其内部技能不会列入该列表。

需要移除某个个人 Skill 时，可以说“卸载我的会议纪要技能”。名称不明确或有多个匹配项时，助手会先请你明确目标。内置 Skill 由系统提供，不能卸载；计划模式可以查看列表，但不能卸载。

卸载会永久删除你的安装副本、技能文件、相关个人配置和凭据绑定，保留任务历史及审计记录，不影响其他用户的安装副本或插件中心已发布的版本。正在运行的任务可能继续使用已加载的技能，后续轮次会按更新后的状态加载。

### 启用、停用、更新与删除 [#personal-content-启用停用更新与删除]

- 停用后，新的任务不会使用该能力。
- 更新会再次执行来源和风险检查。
- 删除会永久移除个人能力、相关个人配置和凭据绑定，无法恢复。
- 已经发生的任务历史和审计记录仍保留必要的能力名称、来源和版本信息。

更新个人技能时，窗口会加载当前展示名称、说明、完整正文和文件清单。技能标识保持不变。无论最初是手动创建还是导入 ZIP，都可以通过“更新方式”的单选项选择：

- **编辑技能内容**：修改展示名称、说明和正文。原有脚本、模板、图片及其他文件都会保留，未编辑的技能配置也会保留。
- **替换完整技能包**：上传包含全部所需文件的 ZIP。新包会完整替换当前技能，旧包中未包含在新包内的文件将被删除。需要修改脚本或资源时，可以先“下载完整技能包”，在本地修改后上传。

点击“查看变更与风险”，核对新增、修改、删除的文件，以及更新后技能的风险提示。存在删除项时，需要单独确认这些文件的删除，再确认更新。检查、切换更新方式或返回编辑均不会修改当前技能。

没有修改正文或其他信息时，编辑方式不能提交。正文过长而无法在线编辑时，仍可以下载和替换完整技能包。如果技能在编辑期间发生变化，请重新打开更新窗口，核对最新内容后再提交。版本升级前尚未确认的旧更新预览，也需要重新检查。

### 申请上架 [#personal-content-申请上架]

在“我的发布”中选择个人能力，填写发布说明并提交。系统会复制一份不可变快照交由管理员审核。提交后继续修改个人能力不会改变待审快照。

每个新发布都需要单独审核。你可以在管理员作出结论前撤回；审核通过后，当前获批发布会出现在插件中心。

## 创建和管理应用 [#create-applications]

应用为重复场景提供受控入口。创建者可以组合模型、指令、插件、Skill、知识库和 MCP，再在组织内共享；应用不会扩大创建者或使用者原本没有的资源权限。

在“我的应用”中，搜索栏右侧可筛选“全部应用”“开发中”“普通应用”或“交互式应用”，并与关键词搜索组合使用。“交互式应用”也包含尚未发布的开发草稿；“普通应用”只显示普通应用。筛选条件会保留在页面地址中，刷新后仍然生效。

### 查看应用详情 [#create-applications-查看应用详情]

“我的应用”优先展示已发布版本。只有草稿的应用显示“草稿”和开发角标；已发布应用不显示开发角标，有未发布修改时在 MCP 数量右侧显示“有新开发版”。详情弹窗会单独展示开发版的名称、描述、图标、插件 / Skill、知识库和 MCP 数量，以及最近保存时间。“开发中”筛选包含纯草稿和有新开发版的应用，每个应用只显示一张卡片。

开发入口位于卡片右上角的三点菜单：已有开发工程选择“继续开发”，否则选择“开发新版本”。卡片上的“使用”始终打开已发布版本。

在“我的应用”“共享给我的应用”或“应用中心”点击应用卡片主体，即可查看名称、完整说明、创建者、类型、模型、版本（如有）和时间信息，以及按插件、技能、MCP 服务、知识库分组的资源列表。“使用”和更多操作菜单仍独立操作，不会打开详情。

- “我的应用”的卡片和详情展示相同的已安装发布版本，包括名称、说明、图标与资源。尚未发布的应用展示当前配置，开发草稿单独展示。共享应用和应用中心的资源列表以对应的已发布版本为准，不会展示创建者尚未发布的资源选择。
- 资源列表优先显示实际配置的资源名称；与应用声明的名称不同时，会在下方补充“应用声明”。绿色勾图标表示“已配置”，将鼠标移至图标可查看提示。未匹配的资源显示“待配置”，被停用或删除的资源显示“不可用”。“已配置”只表示资源已关联，实际使用仍受凭据、授权和服务状态影响。
- 详情不展示资源 ID、凭据、连接配置或应用指令。查看资源名称不代表获得浏览或管理资源的权限。

### 创建普通应用 [#create-applications-创建普通应用]

1. 进入“插件中心 → 应用 → 我的应用”。
2. 选择“创建应用 → 创建普通应用”。
3. 填写名称、说明并选择内置图标或上传图片。普通应用和交互式应用默认使用彩色立方体图标，已有图标设置会保留。
4. 决定固定模型和推理强度，或允许用户在聊天中选择。
5. 填写应用指令，并选择由你管理的插件、Skill、知识库和 MCP。
6. 保存后先点击“使用”验证完整流程。

应用指令不会向被共享者展示。插件会使用创建者已绑定的插件凭据；MCP 工具可能产生外部副作用，添加前必须确认用途和权限。

### 在对话中开发交互式应用 [#create-applications-在对话中开发交互式应用]

1. 在“我的应用”选择“创建应用 → 用对话创建交互式应用”，填写名称并开始开发。也可以在普通任务中直接说“帮我开发一个 LinkSense 交互式应用”。
2. 在开发对话中描述需求。右侧的应用预览会随修改自动更新，无需导出和导入文件。点击预览上方的应用名称或描述即可编辑，停止输入后自动保存，离开输入框时也会保存。
3. 在预览中操作应用，提交真实任务、上传文件、查看结果。调试过程保存在应用的“调试对话记录”中，不会进入侧栏、普通任务搜索或归档列表。
4. 在“配置能力”中搜索、选择或移除应用可以使用的插件、技能、知识库和 MCP。保存后，选择会写入应用配置并用于预览，安装或更新时随应用一起保存。若对话同时修改了应用，请重新读取配置后再保存。“调试日志”会收集预览中的错误，助手也可以读取并修复。
5. 确认效果后点击“发布”，在弹窗中确认后应用会启用，即可在“我的应用”使用。以后从应用三点菜单选择“继续开发”或“开发新版本”，修改后点击“发布更新”并确认。新版只会立即对创建者生效；组织共享需重新保存共享配置，应用中心也需单独更新上架，使用者再手动安装更新。

源码暂时不完整时，预览保留上一次可运行的版本；正在执行的调试任务会先完成，再切换到最新修改。发布会检查是否有尚未预览的新修改；确认窗口打开后若内容发生变化，需要重新确认。

应用名称右侧以轻量标签显示当前内容的“草稿”或“已发布”状态；发布后继续修改会重新显示“草稿”。右上角三点菜单集中提供“发布／发布更新”“配置能力”“新建调试对话”“调试对话记录”和“调试日志”。应用预览会自动更新，无需手动刷新。选择记录或日志后，下方显示对应内容；点击其右上角的关闭按钮即可返回应用，已填写的内容会保留。调试对话记录只在提交调试请求后出现，可查看输入、输出、文件和运行状态。修改代码、刷新预览或尚未提交任务时，不会产生空记录，也不会展示内部预览版本号。点击“新建调试对话”会重置预览，已经提交过的测试会保留；旧记录可单独删除。正在进行的测试需先停止并处理待办，再重新开始或删除应用。

草稿修改不会改变已安装、已共享或已上架的版本。“发布更新”成功后只对创建者生效；需重新保存组织共享或提交应用中心上架更新，使用者手动安装后才能使用新版。具体步骤见[共享应用与配置外部访问](#application-access)。

归档或删除开发任务不会删除应用、开发草稿和调试对话记录。可以在“我的应用”中找到应用，从三点菜单选择“继续开发”接着修改；原任务已删除时会自动创建新任务，并保留原来的源码和测试记录。在三点菜单选择“删除开发草稿”，会清理草稿和调试对话记录，保留已发布应用。选择“删除”则删除整个应用及其草稿和调试记录。两种操作均保留开发任务、正式任务和工作区文件，关联运行资源由后台清理。

### 标注预览，让 LinkSense 修改 [#create-applications-标注预览让-linksense-修改]

在开发界面右上角、三点菜单左侧点击“标注”，点选或拖动框选需要调整的内容。点击选区旁的“问 LinkSense”，在弹出的输入框中填写要求并点击“添加标注”。可以继续选择其他内容，为每处分别添加要求；每条标注都会显示编号，在标注列表中可定位、删除、清空或一次发送全部标注。

标注发送到左侧开发对话。LinkSense 根据所选内容修改当前应用，发送后预览恢复自动更新。开发对话正在处理其他要求时，标注进入同一对话的待处理列表，不会新建试运行任务。标注模式下页面按钮不会触发应用操作；可以退出标注模式继续试用应用，再次进入时已添加的标注仍会保留。

标注期间暂停自动更新，避免选中的位置改变。如果其他操作更新了应用，系统会提醒重新选择；发送失败时标注会保留。清空并退出标注，待预览更新后再选择即可。

### 修改应用图标和信息 [#create-applications-修改应用图标和信息]

在开发界面中点击名称左侧的应用图标，可以选择预设图标或上传图片，同时修改名称和描述。在“我的应用”的应用菜单中，已安装应用选择“编辑”，开发草稿选择“编辑应用信息”，也可以修改这些信息。图片支持 PNG、JPEG、WebP，最大 512 KiB，宽高不超过 1024 像素。

也可以在开发对话中上传图片，说“把这张图片设为应用图标”，或直接要求修改名称、描述。修改会保存到正在开发的应用并更新预览，发布后在“我的应用”中使用。

### 导入交互式应用 [#create-applications-导入交互式应用]

选择“导入交互式应用”，上传根目录含 `manifest.json` 和 `index.html` 的 ZIP 包。页面在隔离 iframe 中运行，并通过 LinkSense SDK 启动任务或控制原生聊天区。完整包结构和接口见[开发交互式应用](../../developer-guide/interactive-application.mdx)。

准备应用包时，可从导入弹窗打开“资源声明清单”，选择应用需要的资源。关闭清单后会返回导入弹窗，已选择的应用包会保留。

更新交互式应用包时，Manifest 的版本号可保持不变或提高，不能低于已有最高版本。点击“更新”后，新包和资源配置立即对自己生效。组织共享需重新保存，应用中心需另行上架，由使用者手动安装更新。当前用户的该应用有正式任务正在进行时，更新会被阻止；请停止任务或等待完成。

### 更新、停用与删除 [#create-applications-更新停用与删除]

已有任务的下一次执行使用当前已安装版本，不会一直固定在创建任务时的版本。正在执行的任务不会中途切换版本，历史结果也不会被改写；仅打开或刷新历史任务不会自动安装更新。

普通应用和交互式应用均可通过三点菜单的“编辑”修改后，点击“保存”。编辑时保留当前版本号；没有版本号时填入 0.0.1。可自行填写更高版本号（格式为 x.x.x），不能降低版本。保存成功后，自己的应用卡片、详情和后续任务一起采用新配置；版本号不变也会保留独立记录。保存失败不会留下部分修改。当前用户的该应用有正式任务正在进行时，必须先停止任务或等任务完成。组织共享和应用中心需分别更新，由使用者手动安装。创建、导入和更新应用包的按钮分别为“创建”“导入”“更新”，成功后同样立即对自己生效。

- 编辑配置会保存到当前应用；组织内共享需通过“保存共享”更新，应用中心需单独更新上架版本。更新不改变正在运行的轮次或历史结果。
- 停用后不能开始新任务，既有任务记录仍保留。
- 必需依赖被停用、删除或失去权限时，应用会显示不可用，修复依赖后再启用或试用。
- 删除应用后不再出现在插件中心，也不能开始新任务；既有个人任务不会随应用删除。

发布给组织前，继续完成[共享与外部访问](#application-access)和[应用用量](#application-usage)检查。

## 使用共享和应用中心的应用 [#organization-apps]

组织应用可以把模型、插件、Skill、知识库和固定指令组合成可安装的应用包或由创建者托管的在线应用服务，适合标准化工作流程。

应用分为普通应用和交互式应用。交互式应用会打开开发者提供的业务界面，并在右侧分栏显示 LinkSense 原生聊天。拖动两个区域之间的分隔线可以调整聊天宽度；你也可以隐藏或重新显示聊天区，任务和应用中的数据不会因此停止或丢失。

### 找到应用 [#organization-apps-找到应用]

进入“插件中心 → 应用”：

- “共享给我的”展示用户或用户组直接授权给你的版本；
- “应用中心”展示管理员已审核并公开上架的版本；
- “我的应用”展示你创建的应用，以及已经安装为个人副本的应用。

应用卡片会标明可用的使用方式。详情会说明创建者、用途、版本、使用说明和应用资源摘要。

### 选择使用方式 [#organization-apps-选择使用方式]

普通应用可以提供一种或两种方式；交互式应用只提供“在线应用服务”：

| 使用方式 | 安装后得到什么 | 资源和配置由谁维护 |
| --- | --- | --- |
| 应用安装包 | “我的应用”中的独立副本，可以查看应用源码并继续编辑 | 应用及随附插件、Skill 保存到你的账号；自行配置应用可能需要的凭据、知识库和外部连接 |
| 在线应用服务 | 无需安装为自己的本地应用，在线使用创建者发布的服务 | 使用创建者已配置的凭据，由创建者维护应用版本和资源；你不能因此浏览这些资源的内容或配置 |

安装前检查版本、使用说明和所需配置。应用安装包可以填写安装后的应用名称；安装后若提示“需要完成配置”，先在“我的应用”补齐资源和凭据。在线应用服务安装完成后，选择“使用”启动任务。

### 启动应用任务 [#organization-apps-启动应用任务]

选择已经安装的应用或服务，并按应用页面填写请求。根据应用配置：

- 模型可能由创建者固定，也可能由你选择。
- 在线应用服务中的插件、Skill、知识库和应用指令由创建者维护；应用安装包中的个人副本由你维护。
- 服务应用的知识库只在应用任务中用于检索，不因此授予你浏览、预览、下载或管理知识库的权限。

安装会固定一个明确版本。创建者重新共享或应用中心通过新版本后，页面会显示“发现新版”，但不会静默替换你的安装。结束该应用所有正在运行的正式任务后，手动安装更新；成功后，新任务和已有任务的下一次执行使用新版本，正在运行的轮次和历史结果不会被改写。应用安装包的更新会说明哪些个人配置可以保留；更新失败时继续保留原安装。

交互式应用任务会一直保留在左侧任务列表中。即使你切换到其他任务、刷新页面或关闭后重新进入，LinkSense 也会打开该任务当前记录的应用版本，恢复此前已经产生的结构化数据，并继续接收后续结果；这不会重新执行任务，也不会单因打开页面就安装新版本。手动更新安装后，已有任务在下一次执行时采用新版本，之后重新进入会打开该任务已采用的版本。

### 应用不可用 [#organization-apps-应用不可用]

应用被停用、服务授权被撤销、应用中心服务被下架，或必需模型、能力、凭据、知识库不可用时，不能开始新的服务任务。既有个人任务记录仍保留。独立安装的应用包不会因共享授权撤销而被删除，但仍受其个人资源状态和管理员风险治理限制。可联系应用创建者或管理员处理依赖。

如果需要创建或维护入口，参见[创建和管理应用](#create-applications)；组织共享和 iframe 访问分别由[共享应用与配置外部访问](#application-access)说明。

### 创建者查看用量 [#organization-apps-创建者查看用量]

应用创建者可以打开应用卡片的“更多操作 → 用量统计”，按全部时间、最近 7 天、最近 30 天或自定义日期查看使用人数、任务数、轮次数、模型调用、Token 和费用。统计页同时提供趋势、Token 与费用构成以及按模型和用途汇总的明细，但不会向创建者展示使用者姓名或邮箱。

Token 和费用只覆盖系统开始采集后的调用。任务和轮次可以包含更早的历史记录，但系统不会使用当前模型价格推算更早的 Token 或费用；没有可靠价格快照的 Token 会明确标记为未定价。

指标口径和范围选择见[查看应用用量](#application-usage)。

### 与普通任务的区别 [#organization-apps-与普通任务的区别]

普通任务由你逐轮选择资源；在线应用服务由创建者维护受控组合，应用安装包则形成由你维护的独立副本。不要把任何应用入口当作额外权限来源，所有资源访问仍由 LinkSense 在服务端校验。

## 共享应用与配置外部访问 [#application-access]

### 组织内共享 [#application-access-组织内共享]

在“我的应用”的应用卡片三点菜单中选择“组织内共享”，添加一个或多个用户或用户组，并选择使用方式：

- **应用安装包**：仅普通应用可用。用户安装为自己的应用，自行配置应用可能需要的凭据，使用者能够看到应用源码。知识库和外部连接也由使用者自行配置。
- **在线应用服务**：发布应用为在线服务，用户无需安装为自己的本地应用，将使用你已配置的凭据在线使用应用。交互式应用只支持此方式。

普通应用可以同时提供两种方式。被共享者需要明确安装后才能使用；服务使用者不能因此浏览应用指令、创建者凭据或应用知识库中的文档。

取消共享会阻止新的服务安装和使用，但不会删除已经安装的独立应用包。既有任务及其历史结果仍属于原使用者。用户同时通过用户和用户组获得授权时，移除一个授权来源不一定立即失去访问。

#### 更新已共享的交互式应用 [#application-access-更新已共享的交互式应用]

“发布更新”或“更新应用包”成功后，新版本只对创建者生效。组织内共享和应用中心需要分别更新，其他用户手动安装后才会使用新版；草稿编辑不会提前发布。

1. 在开发界面点击“发布更新”并确认，或从应用卡片菜单选择“更新应用包”，导入新版 ZIP。
2. 确认新包所需资源均已配置，并填写更高的 `x.x.x` 正式版本号。
3. 再打开“组织内共享”并点击“保存共享”，向接收者提供本次已发布版本。窗口默认选中原来的共享用户和用户组，可以按需调整。

接收者看到“有更新”后，需要手动安装。该用户的此应用还有任务运行时，须停止相关任务或等待完成后再安装。安装成功后按以下规则使用：

| 使用场景 | 使用的版本 |
| --- | --- |
| 新建任务 | 当前已安装版本；发现更新不等于已经安装。 |
| 在已有任务中发起下一次执行 | 当前已安装版本，保留已有对话和工作文件。 |
| 任务已经开始执行 | 保持本次已采用的版本，不在执行中途切换，也不能同时安装更新。 |
| 只打开或刷新历史任务，没有提交请求 | 不会触发执行或自动安装更新。 |

历史结果不会被新版本改写。任务文件和对话上下文会保留；若安装失败，原已安装版本保持不变。

应用中心提供当前已审核上架的版本，用户仍需手动安装。发布应用或“保存共享”不会同时更新应用中心，需要单独提交并完成审核上架。

### 外部 iframe 访问 [#application-access-外部-iframe-访问]

只有应用创建者可以打开“更多操作 → 外部访问”。配置步骤为：

1. 添加允许嵌入的网站来源，每行一个且不能重复；生产环境使用 HTTPS，本地调试可使用 localhost 或 127.0.0.1 的 HTTP 地址。
2. 选择“需要认证”或“不需要认证”。
3. 为每个来源按需配置最多 4 个内置问题，每个问题最多 500 个字符。
4. 保存安全配置并复制对应来源的 iframe 地址或代码片段。
5. 在宿主网站完成集成测试后，再开启“启用外部访问”。

允许来源必须与实际宿主页面的协议、主机和端口完全一致。关闭外部访问后，新的外部请求和已经打开的外部会话都会失效。

#### 外部访问如何更新版本 [#application-access-外部访问如何更新版本]

外部访问使用创建者当前的正式版，无需等待重新组织内共享或应用中心上架，也不要求外部用户手动安装。

- 全新的外部会话从创建者当前正式版开始。
- 已有外部用户在新建任务或继续对话时，如果该用户在此应用中的全部任务均已结束，会在启动前自动更新到创建者当前正式版。
- 只要还有任务正在启动、运行或停止中，就继续使用原版，不影响正在运行的任务。更新进行期间，其他新的启动请求会提示稍后重试。
- 更新失败时，本次启动会提示错误，原版本、对话和工作文件保留；再次启动时重新检查更新。
- 仅打开页面、刷新页面或恢复会话不会触发更新；未发布草稿不影响外部用户。

需要认证的访问和公开访问均遵循这些规则。组织内共享及应用中心仍采用手动安装规则。

### 需要认证 [#application-access-需要认证]

受信任业务后端使用 App ID 与 App Secret 申请短时 ticket，业务前端只把 ticket 交给 iframe。App Secret 只能保存在服务端；不要放入浏览器代码、URL、日志或截图。轮换 Secret 会立即使旧 Secret 及相关未使用 ticket 失效。

详细请求流程、用户身份和 `postMessage` 协议见[嵌入 LinkSense 应用](../../developer-guide/embed-application.mdx)。

### 不需要认证 [#application-access-不需要认证]

公开模式不要求业务后端签发 ticket，但仍只接受允许来源。任何能访问该页面的人都可能创建应用会话，因此只适用于无需识别外部用户、风险可控的内容；不要把公开模式当作访问控制。

## 查看应用用量 [#application-usage]

应用创建者可以在“我创建的”应用卡片选择“更多操作 → 用量统计”。其他被共享用户和管理员的全局统计权限不会自动获得该应用的创建者视图。

### 选择范围 [#application-usage-选择范围]

可以查看全部时间、最近 7 天、最近 30 天或自定义日期。页面展示使用人数、任务数、实际轮次、模型调用、Token 和费用，并提供趋势、Token/费用构成、按模型和按用途明细。

“使用人数”是所选周期内创建过应用任务或实际发起过轮次的去重用户。统计不会展示使用者姓名或邮箱。

### 理解数据 [#application-usage-理解数据]

- 任务按创建时关联的应用计数，后续改名或更新应用不会改变历史归属。
- 轮次只计算真实执行，不把草稿、重连或重复事件算作新轮次。
- Token 和费用仅覆盖系统开始采集后的模型调用；更早任务仍可计数，但不会用当前价格倒推费用。
- 没有可靠价格快照的 Token 会标记为“未定价 Token”。
- 费用使用调用发生时保存的价格，后续调价不回算历史。

管理员还可以在[全局用量统计](../../admin-guide/models-and-usage.mdx#usage)中按应用比较全系统用量，但该页面遵循管理员的数据边界。

## 管理插件凭据 [#credentials]

插件凭据是插件访问外部服务时使用的 API Key、Token 等授权信息。添加凭据并关联插件后，你使用该插件时会自动使用这些信息。密钥等授权信息保存后不会再次显示。

### 新增凭据 [#credentials-新增凭据]

1. 进入“设置 → 插件凭据”，选择“新增凭据”。
2. 填写便于辨认的名称和服务标识。名称中不要包含密钥。
3. 按插件说明填写配置项名称和对应的授权信息，可添加多项。
4. 保存后，选择“关联插件”。

编辑时，授权信息留空会保留原有值；填写新值会替换对应信息。

### 查看关联和配置状态 [#credentials-查看关联和配置状态]

每条凭据显示关联的插件数量。同一个插件使用多项信息时合并展示，例如“用于 1 个插件”“已关联 2 项信息”。

- **凭据已配置**：插件声明的配置项已有对应信息。这不代表已验证外部服务连接。
- **还有信息未配置**：展开“查看配置详情”了解缺少的项目，再从插件右侧的三点菜单选择“补充配置”。
- **此凭据已停用**：选择“启用凭据”以恢复使用。
- **关联存在冲突 / 配置需要更新**：检查凭据内容，从插件右侧的三点菜单选择“处理关联”，调整使用的信息。
- **插件不可用**：插件已不可用或你没有权限，可以解除关联或联系管理员。

配置项名称及对应关系位于“查看配置详情”中；在凭据右侧的更多菜单中选择“凭据详情”，可查看服务标识。未关联插件的凭据不会自动用于插件。

### 关联插件 [#credentials-关联插件]

1. 选择“关联插件”，或在已有插件右侧的三点菜单中选择“管理关联”。
2. 选择插件并确认已选择的信息数量。同名配置项会自动匹配。
3. 如有未匹配的项目，选择“选择或调整对应信息”，为插件选择此凭据中对应的信息。如果凭据中尚未保存需要的信息，先编辑凭据补充内容。
4. 选择“保存关联”。插件在后续执行时会使用这些信息。

一个配置项只能使用一个明确的凭据来源。保存关联会更新你为该插件选择的信息。

### 停用、解除关联与删除 [#credentials-停用解除关联与删除]

- **停用凭据**：保留凭据和关联，插件在后续执行时不再使用它。启用后可再次使用。
- **解除关联**：在插件右侧的更多菜单中选择“解除关联”，确认后，解除此凭据与指定插件的全部关联，凭据本身保留。
- **移除单项关联**：在配置详情中移除某项关系，凭据中保存的信息保留。
- **删除凭据**：永久删除凭据及关联记录，无法恢复。

凭据仅供你自己的插件使用，不会自动使用其他用户的凭据。
