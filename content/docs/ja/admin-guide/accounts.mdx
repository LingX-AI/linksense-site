メンバーアカウントの管理、コラボレーションのためのグループ組織化、役割とコンテンツアクセスの境界確認。

## ユーザー管理 [#users]

<Callout type="info" title="管理者の運用">

**設定 → ユーザーとグループ → ユーザー**開け。 管理者はシステム設定でオープン登録を有効にすることができます。

</Callout>

### ユーザー作成 [#users-create-users]

名前、ユニークなメールアドレス、役割、任意のグループを提供しましょう。 新規ユーザーにはローカルパスワードがなく、LinkSenseは自動的に招待を送りません。

ユーザーは設定済みのSSOやTeamsでサインインするか、メールでローカルパスワードの設定を依頼できます。 管理者はユーザーパスワードの設定、閲覧、インポート、リセットを行うことはできません。

### Excel import [#users-excel-import]

テンプレートをダウンロードし、名前、メールアドレス、役割、グループを入力してアップロードします。 インポートは必要項目、グローバルなメールの一意性、有効なロール、既存のグループ名を検証します。 テンプレートにはパスワード欄がなく、修正のために無効な行を報告します。

### 編集 [#users-edit]

名前、メールアドレス、役割、グループメンバーを更新できます。 メールの変更は即座にすべてのセッションと未使用のパスワードリンクを取り消し、新しいメールでのサインインが必要です。

### クレジットクォータ [#users-credit-quotas]

週ごとのノルマを個別に、またはクレジット単位でまとめて設定しましょう。 正の数字は小数点以下6桁まで許容されます。 空白は無制限を意味し、一括変更は選択されたユーザーにのみ影響します。

制限に達すると、実行中のタスクが完了する間に新しいタスクができません。 毎週月曜の深夜にシステムタイムゾーンで再設定されます。

作成、インポート、または自己登録の会員は、デフォルトの週単位の割り当てを共有[割当管理](./models-and-usage.mdx#quota-settings)。 デフォルトを保存しても既存のメンバーには影響しません。上書きを意図している場合は**全員に上限を適用**を使います。

### 無効化と復元 [#users-disable-and-restore]

無効にすると新規ログインが拒否され、次のリクエストでアクティブなセッションが終了し、新しいアクティビティやダウンロードがブロックされ、開始されていないリクエストがキャンセルされます。 ランニングカーブは元の最終状態まで続きます。 歴史、知識ベース、公開リリース、監査データは残っています。

復元すると再びアクセスが許可されますが、キャンセルされたキュー中のリクエストは再開されません。

### 管理者保護 [#users-administrator-protection]

管理者は自分自身を無効化または降格することができず、少なくとも1人のアクティブな管理者が残っていなければなりません。 サーバーは同時進行の変更中でもトランザクション形式でこれをチェックします。 却下された試みは監査されます。

## ユーザーグループ管理 [#groups]

<Callout type="info" title="管理者の運用">

**設定 → ユーザーおよびグループ グループ グループ→**開け。 グループは承認のための利便性であり、組織の階層構造ではありません。

</Callout>

### ルール [#groups-rules]

- グループはフラットであり、子グループは含めません。
- ユーザーは複数のグループに属している場合があります。
- 名前は世界的に一意です。
- メンバーシップはユーザーや管理者の役割を変えることはありません。

### 作成と編集 [#groups-create-and-edit]

名前とオプションの説明を追加し、既存のユーザーを選択してください。 会員の追加・削除は、関係者と時間を記録します。

通常の除去は関係を取り消しつつ、必要な歴史は保持します。 ユーザーは他のグループや直接共有を通じてナレッジベースへのアクセスを保持することができます。

### 会員一覧 [#groups-view-memberships]

ユーザーテーブルは名前のコンパクトな部分集合のみを表示することがあります。 意思決定前に、グループの詳細やアクセス可能なオーバーフロープレビューを活用してください。

### グループを削除する [#groups-delete-a-group]

削除は取り返しのつかない。 同じ取引で、孤児的な行を避けるためにアクティブおよび取り消されたメンバーシップや知識ベースの付与も削除されます。 パーマネント監査はグループIDと影響を受けた数のメタデータを最小限に抑えます。

削除前に、グループから派生したアクセスを特定し、必要に応じて代替アクセスを作成し、使用報告において現在のメンバーシップの意味論を考慮してください。

### 使用報告 [#groups-usage-reporting]

グループ利用は、各ユーザーの活動を現在所属しているすべてのグループに適用します。 行は重複しており、合計を合わせてはなりません。

## 役割と認可境界 [#roles]

<Callout type="info" title="管理者の運用">

**設定 → ロールと権限**は読み取り専用の概要です。 カスタムロールは利用できません。

</Callout>

### 固定役割 [#roles-fixed-roles]

- **ユーザー**個人のタスク、能力、所有知識ベースを管理し、与えられたリソースを活用します。
- **管理者**また、ユーザー、グループ、カタログガバナンス、ナレッジガバナンス、モデル、設定、健康、監査、利用管理も行っています。

スーパー管理者、部門管理者、読み取り専用管理者、カスタム権限バンドルはありません。 最初の管理者には隠された権限はありません。

### 役割はコンテンツアクセスではありません [#roles-role-is-not-content-access]

管理ガバナンスは、他のユーザーのタスク、個人能力コンテンツ、知識ベース文書を自動的に公開するものではありません。 所有権と共有がコンテンツアクセスを引き続きコントロールしています。

### 役割の変更 [#roles-change-a-role]

ユーザー管理から別のアカウントを変更してください。 管理者を降格する前に、別の現役管理者が残っていることを確認してください。

管理者は自分自身を降格・無効化できず、最後の有効な管理者を降格・無効化することもできません。 サーバーは更新トランザクション内でこれを強制します。

### グループと役割 [#roles-groups-and-roles]

グループは固定会員制およびリソース助成金を提供します。 ユーザーをグループに追加しても管理者にはなりません。
